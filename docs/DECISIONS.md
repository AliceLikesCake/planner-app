# 開發前的決定（2026-10-24）

和 SPEC.md 有出入或 SPEC 沒寫清楚的地方，以這份為準。

1. **開發階段是 8 個**：SPEC 第 9 節列的 8 個階段。PROMPTS.md 第 0 段寫的「9 個」是筆誤。
2. **Vue 專案**：資料夾裡已經有規格和素材，用 create-vue 在暫存資料夾建好專案後再搬進來，不覆蓋既有檔案（TypeScript、Router、Pinia、Vitest、ESLint、Prettier）。
3. **推播通知（Web Push）先不做**：需要伺服器端排程（Supabase Edge Function + 排程 + VAPID 金鑰）。其他功能都穩定後再加。設定頁的推播相關開關先做 UI、存設定值。
4. **重複待辦**：tasks 只存一筆（`repeat` 欄位）。顯示某一天時即時算出當天該出現的重複待辦；那一天打勾時，才為那一天建立一筆完成紀錄（實作方式在第 3 階段決定，必要時加欄位或表，並更新 schema.sql）。
5. **「簽合約／勞報單」待辦合成一筆**：每個接案最多一筆 `gig_kind='sign_docs'` 的待辦（符合現有唯一索引）。合約和勞報單都簽了才自動完成；任一個改回未簽就恢復未完成。
6. **深色模式先不做**：tokens.css 只有淺色。設定頁的開關先保留但停用（或隱藏），之後設計好深色配色再做。
7. **設定裡沒有對應欄位的開關**（全部完成閃亮音效、完成的蛋糕收進月曆、只在 Wi-Fi 同步、每天自動備份）：到第 8 階段再決定要不要做，要做時再加欄位並更新 schema.sql。

## 第 3 階段（2026-10-24）

8. **重複待辦的完成紀錄**（第 4 點的實作）：新增 `task_completions` 表（`task_id` + `date` 為主鍵，含 `done_at`）。重複待辦在某一天打勾時寫一筆、取消時刪掉；不重複的待辦照舊用 `tasks.done` / `done_at`。重複規則：每天＝開始日以後每天；每週＝同一個星期幾；每月＝同一天，該月沒有那天（29–31 號）就落在月底。
9. **「一天最多疊幾層」就是合併的門檻**：待辦件數超過 `settings.max_layers`（預設 8）才合併成類別層，所以預設行為等於 SPEC 的「> 8 件合併」。
10. **蛋糕層的順序**：完成的層依完成時間由下往上疊，未完成的虛線層在最上面。
11. **另外三種甜點的造型**（設計稿沒有）：提拉米蘇＝可可粉頂面＋奶油球；草莓塔＝淺圓柱＋花邊塔殼＋一圈草莓；生乳捲＝鮮奶油頂面＋奶油球＋草莓。
12. **其餘調色盤的蛋糕層顏色**：蜜桃 `#F3CDB8`（設計稿）、薄荷 `#BCE0D6`、粉紅 `#EFC6D9`、奶茶 `#D9D2C7`，已加進 tokens.css 的 `--cake-*`，讓改了顏色的類別也有對應的蛋糕層。
13. **今日頁的星期按鈕只換甜點預覽**：待辦清單和蛋糕層永遠是今天的，跟設計稿一致。

## 第 4 階段（2026-10-24）

14. **行程產生的待辦用哪個類別**（規則 7）：用同名的待辦類別（工作、接案、學習、健康）；待辦沒有的類別（約會聚餐、旅行）歸到「生活」。非整天的行程，第一天的待辦帶開始時間，其他天不帶。
15. **行程產生的待辦不列在月曆的待辦清單**：月曆已經顯示那個行程，這些待辦的 `show_in_calendar` 設為 false，避免同一件事出現兩次。它們照常出現在今日待辦、可以打勾疊蛋糕。
16. **月曆的欄位順序跟著「一週從」設定**（週一／週日）。設計稿是週日開頭，app 預設週一（settings 預設值）。
17. **跨天長條用「車道」排**：同一個行程在一週內固定在同一列，所以長條不會在格子間上下跳；每格最多 3 列，其餘顯示「+N」。
18. **月曆的待辦清單只顯示、不能打勾**（照設計稿）。打勾在今日頁。
19. **編輯與刪除**（SPEC 沒寫，使用者要求）：編輯沿用新增畫面（`/edit/task/:id`、`/edit/event/:id`），最下面有刪除，要按兩次。今日頁的待辦往左滑露出「編輯」「刪除」，點一下照舊是打勾；月曆下方的行程和待辦點一下就是編輯。行程產生的待辦按編輯會打開那個行程。刪除重複待辦會整組刪除。

## 通用規則

20. **所有功能都要能編輯和刪除**（使用者要求，2026-10-24）：每一種使用者建立的資料（待辦、行程、習慣、接案、記帳、類別、預算…）都要有編輯和刪除，就算 SPEC 只寫了新增畫面。做法照第 19 點：編輯沿用新增畫面（`/edit/<種類>/:id`），刪除按兩次；列表點一下打開編輯，點一下已經有別的用途的（例如今日待辦是打勾）就往左滑出「編輯」「刪除」；自動產生的資料（`source` = gig / event）從來源去改。

## 第 5 階段（2026-10-24）

21. **連續天數只算「該做的那幾天」**：沒排到的星期幾不會中斷連續；今天還沒戳破也不算中斷（今天還沒結束）。習慣建立之前的日子不算沒做到。
22. **「最長連續」是從建立到今天的最長紀錄**，不只看本月；「本月完成」和百分比只看本月到今天為止（百分比＝完成天數 ÷ 該做的天數）。
23. **每月紀錄的格子**：做到＝習慣顏色底＋深色邊框；該做沒做＝淺灰底；沒排到的那天＝只有淡色數字；今天還沒戳破和未來＝虛線圓。今天加外圈。
24. **習慣的編輯入口**：泡泡點一下是戳破，所以「編輯」按鈕放在每月紀錄的分頁旁邊，編輯目前選的那個習慣；刪除在編輯畫面最下面（按兩次），打卡紀錄一起刪除。
25. **取消戳破沒有音效**（照設計稿），戳破是 water-bubble（rate 1.35），全部戳破再接 fairy-glitter。

## 第 6 階段（2026-10-24）

26. **勾「交稿」「上線」時，對應的待辦也跟著打勾**：接案頁勾交稿 →「準備交稿」完成；勾上線 →「確認貼文上線」完成；取消就恢復。只在接案頁那個圈圈改變時同步，所以在今日頁自己打勾不會被蓋掉。（SPEC 只寫了簽約文件，這兩個比照辦理。）
27. **接案自動記的收入**：金額＝合作金額、分類＝接案、備註＝品牌名、日期＝入帳日。之後改合作金額，收入會跟著改；但如果那筆收入的金額在記帳頁被手動改過，就不再跟（transactions 沒有 source 欄位，用「金額是否還等於舊的合作金額」判斷）。規則 4 關閉時，標記已入帳不會記帳，改回待入帳也不會刪任何收入。
28. **規則 1 的開關**：設定的「接案日期加到月曆」和每個接案自己的開關都要開才會建立；任一個關掉，下次同步這個接案時會移除它產生的行程。
29. **簽約待辦的日期**：第一次產生時放在明天；完成後如果又有文件改回未簽，重新打開並移到明天。
30. **刪除接案**：它產生的行程和待辦一起刪除；你手動建、只是「關聯」到這個接案的待辦會保留，只解除關聯（資料庫的 tasks.gig_id 是 ON DELETE CASCADE，所以先解除再刪）。有記帳收入時，編輯畫面的刪除按鈕上方會出現「同時刪除記帳裡的這筆收入」開關（預設開）。
31. **接案的編輯入口**：點卡片上半部（品牌那一列）打開編輯；五個圈圈照舊是點一下切換。月曆上接案產生的行程、今日頁接案產生的待辦，按編輯都會打開那個接案。已入帳的接案，編輯畫面多一個「已入帳」日期可以改。
32. **規則 5**（記帳 → 接案）：記一筆和編輯一筆都走 `recordTransaction` / `updateTransaction`，收入選了接案就把那個接案改成已入帳。
33. **合作形式加上 Threads、拿掉部落格**（使用者要求）：選項為 IG 貼文、IG Reels、限動、Threads、YouTube。存在 `gigs.formats`（例如 `threads`），資料庫不用改；以前存過的 `blog` 不會顯示，下次編輯儲存時會一併清掉。
34. **接案行程在月曆上依種類上色**（使用者要求）：交稿＝薰衣草、上線＝霧藍、入帳＝薄荷，跟新增接案畫面日期旁的圓點同色（取自 AddCollab 設計稿）；下方列表的標籤顯示「交稿／上線／入帳」。篩選「接案」時三種都會出現。其他行程照舊用類別顏色。
35. **月曆篩選涵蓋行程和待辦**（使用者要求）：篩選列是行程類別和待辦類別的聯集，同 key 的合成一個（工作、接案、學習、生活、健康、約會聚餐、旅行，再加使用者自訂的類別）。選了之後，月曆格子、當天行程、當天待辦都只顯示那一類。

## 第 7 階段（2026-10-24）

36. **記帳的「月」跟著「每月起算日」**：設定是 1 號就是自然月；設定成發薪日 5 號，「10 月」就是 10/5 – 11/4。結餘、收支、預算、分類統計、明細都用這個範圍。
37. **超支**：預算條變紅，右邊的「剩 $X」改成紅字「超支 $X」。
38. **明細每筆的名稱**：有備註就顯示備註，沒有就顯示分類名稱；下面一行固定是分類（不顯示時間）。點一下打開編輯，刪除在編輯畫面最下面（按兩次）。
39. **記一筆選接案收入**：只列出還沒有記帳收入的接案（每個接案只能有一筆，見 schema 的 transactions_gig_uniq），未入帳的排前面。選了會自動帶入合作金額，備註填「{品牌} 接案款」（不會蓋掉你自己打的備註）。
40. **刪除連到接案的收入不會把接案改回待入帳**（SPEC 只寫了接案 → 記帳這個方向）；編輯畫面會提示這一點。要改回待入帳，到接案頁點「入帳」圈圈，那筆收入會一起刪掉。
41. **匯出 Excel 只有接案收入和記帳明細**（使用者要求，取代 SPEC 4.7 的四項內容）：記帳頁、接案頁和設定頁的「匯出 Excel」都打開同一頁 `/settings/export`，內容一律只有「接案收入」和「記帳明細」，兩項預設勾選、範圍預設「今年」（報稅用）；不匯出待辦和習慣紀錄。記帳明細多一欄「產品類別」：連到接案的收入會填那個接案的產品類別。SheetJS 依官網方式從 cdn.sheetjs.com 安裝 0.20.3，只在按下匯出時載入。
42. **匯出範圍怎麼算**：「本月／上個月」跟著每月起算日（同記帳頁）。接案收入：已入帳的看入帳日；未入帳的看交稿、上線、預計入帳日有沒有落在範圍內（都沒填就看建立日期）。
43. **CSV**：一個 CSV 只能放一張表，所以選了多項內容時，每項各下載一個 CSV 檔；檔案開頭加 BOM，讓 Excel 正確顯示中文。檔名是「內容名稱_期間」，例如「接案收入_2026.xlsx」、「我的紀錄_2026-10.xlsx」。
44. **目前存款**（使用者要求，SPEC 沒有）：settings 加 `savings_amount`、`savings_date`、`savings_set_at`。在 `/settings/savings` 輸入「某一天開始前總共有多少錢」和那一天（預設本月第一天），那天（含）之後日期的每一筆收入加上去、支出扣掉，不管是什麼時候記的；輸入時即時預覽「這段期間的收支」和結果。記帳頁總覽卡最上方顯示目前存款，點一下可以修改或選「不使用目前存款」。它不跟著上方切換的月份變，本月結餘照舊只算當月。（沒有 `savings_date` 的舊資料改用「設定之後才記的帳」計算。）
45. **記帳明細可以篩選**（使用者要求）：明細標題下方有「全部／支出／收入」切換，再下面一排分類膠囊（全部分類＋目前收支類型的分類；選「全部」時支出和收入的分類都列出）。每天的合計只算顯示出來的那幾筆；上方的總覽卡和分類統計不受影響。
46. **接案的五個圈圈照順序連動**（使用者要求）：合約 → 交稿 → 上線 → 勞報單 → 入帳（順序見第 56 點）。勾某一步，它前面還沒勾的會一起勾（勾入帳會把今天記為入帳日）；取消某一步，它後面的會一起取消（取消到入帳時，自動記的收入照規則 4 刪掉）。一次存成一筆修改，同步規則照常執行。

## 第 8 階段（2026-10-24）

47. **規則 9 只搬一般的手動待辦**：每天第一次打開 app 時，把昨天以前沒做完、不重複、`source='manual'` 的待辦日期改成今天。重複待辦每天各自算；行程和接案產生的待辦日期由來源決定（搬了也會被同步規則搬回去），所以不搬。
48. **第 7 點的開關怎麼處理**：「全部完成時的閃亮音效」做了（settings 加 `cake_glitter`）；「每週隨機換甜點」做了（用週一日期當種子，同一週在每台裝置都抽到一樣的七種）。「完成的蛋糕收進月曆」先不做（要另外設計月曆怎麼顯示），設定頁不顯示這個開關。
49. **帳號與備份**：資料每次修改都即時存在 Supabase，所以「每天自動備份」「只在 Wi-Fi 同步」「已同步裝置」「還原備份」不做（需要伺服器排程，或瀏覽器拿不到這些資訊）。改成：同步狀態＋「立即同步」（重新讀一次雲端資料）、「下載備份檔」（全部資料存成 JSON）、登出。
50. **設定頁**：深色模式（DECISIONS 6）和意見回饋顯示但停用，標「之後推出／之後開放」。推播相關開關照 DECISIONS 3 只存設定。「快超支提醒」先做 app 內提醒：記帳頁的預算用到 80% 時顯示「已用 X%，快超支了」。記帳區多一列「目前存款」。
51. **類別與顏色有三個分頁**（SPEC 寫兩個）：待辦、行程、記帳（支出／收入）。名稱改的是目前語言的那個（內建類別），自己新增的類別中英文同名。每一種至少要留一個類別；刪除後用到它的資料顯示「未分類」。
52. **PWA 與部署**：vite-plugin-pwa 自動更新、預先快取 app 本體、圖示和音效（資料不快取，永遠從 Supabase 讀）。`vercel.json` 設定 Vite 建置、SPA 改寫和快取標頭。README 和「關於這個作品」頁的截圖用示範資料產生，放在 `public/screenshots/`。

## 部署前追加（2026-10-24）

53. **固定收支**（使用者要求，SPEC 沒有）：新表 `recurring_transactions`（每月或每年，用開始日期的那一天；該月沒有那天就記在月底），`transactions` 加 `recurring_id`（和日期一起唯一，不會重複記）。
    - 記一筆時「重複」選每月／每年：日子到了才自動記一筆（每次打開 app 時補上到今天為止該記的），不會提前，所以目前存款和本月結餘跟實際扣款一致。開始日期在過去的話，會補記過去每一次。
    - 編輯自動記的那筆：可選「只改這一筆」或「這筆和之後每次」（後者改固定收支本身的金額、分類、備註；已經記的其他筆不動），也可以「停止重複」。刪除那一筆只刪它，之後照常記（用 `last_date` 記住記到哪一天，所以刪掉的不會被補回來）。
    - 已經記好的一般帳，編輯時也可以改成每月／每年，它就變成第一筆。
    - 設定 → 記帳 →「固定收支」列出全部，點進去用記一筆的畫面編輯，或「停止重複」（已經記的帳保留，變成一般的帳）。連到接案的收入不能設定重複。明細裡自動記的帳會標「固定」。
54. **快速記帳網址**（使用者要求）：`/add/money?amount=150&note=7-11&type=expense&category=food`，參數都可以省略；amount 接受 Apple Pay 傳來的格式（例如「NT$1,280.00」，四捨五入到元）；category 可以填 key 或中英文名稱。給 iPhone 捷徑、背面輕點和錢包自動化使用。iPhone 的捷徑打開網址會用 Safari，跟主畫面上的 app 是分開登入的，所以要先在 Safari 登入一次。
55. **記帳頁顯示「預計」的固定收支**（使用者要求）：明細上方列出目前顯示的期間內、還沒到日子的固定收支（灰色、虛線圓點），跟著收支和分類篩選，點一下打開那個固定收支；不算進結餘、收支、預算和分類統計。
56. **接案步驟改成合約 → 交稿 → 上線 → 勞報單 → 入帳**（使用者要求，取代 SPEC 4.4 的順序）：勞報單通常上線後才簽。卡片的圈圈、連動規則和匯出的欄位順序都照這個順序。
57. **示範模式**（使用者要求，給履歷和面試用）：登入畫面「先逛逛（示範模式）」不用登入就能進入。資料庫改用記憶體版（`services/memoryBackend.ts`，跟單元測試共用），示範資料由 `services/demo.ts` 透過正常的 store 和同步規則建立（日期以今天為基準，語言跟著目前設定）。所有功能都能操作，但只存在這個分頁裡、不會送到 Supabase，重新整理就回到初始狀態。畫面最上方有示範模式提示和「離開」按鈕；設定頁的「登出」在示範模式就是離開。
